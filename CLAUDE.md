# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, no-build website hosting 20 full TOEIC practice tests (10 from "Hacker Volume 2", 10 from "Hacker Volume 3"). There is no `package.json`, bundler, or test runner — every page pulls its CSS and grading/rendering logic from `assets/` (see below) and keeps only its own `questionsData` inline. The site is fully public — there is no login/auth, no backend, no database. (A Firebase-based login + admin/user-management system used to exist; it was removed, so `firebase-config.js`, `login.html`, `admin.html`, and `config.js` are gone. Don't reintroduce imports to those filenames.)

## Running / previewing

There is no build step. Serve the directory with any static file server and open in a browser, e.g.:

```
npx serve .
```

or just open the HTML files directly (module scripts and relative imports work fine via `file://` in most cases, but a local server avoids CORS/module-loading edge cases).

There are no lint or test commands configured in this repo.

## Architecture

**Practice test pages:**
- Each test lives directly at `Hacker{Vol2,Vol3}_Practice/TEST{NN}/` with `ListeningTest{NN}.html`, `ReadingTest{NN}.html`, an `audio/` folder (MP3 for the listening section), and an `image/` folder (question-set screenshots, e.g. `131-134.png` for RC Part 6/7 passages).
- Every page keeps only its `questionsData` (prompt, options, correct `answer` letter) inline in a `<script>` tag — there is no shared/external question data file per test, and this part is never extracted since it's genuinely unique per-test content, not duplicate code. The rendering/grading logic that used to sit in the same `<script>` tag now lives in `assets/js/` (see below) and is loaded via `<script src="../../assets/js/....js"></script>` right after it.
- `index.html` at the repo root is the landing/dashboard page linking out to all 20 tests' Listening/Reading pages — it has no auth check, anyone with the URL can use it. It links its own `assets/css/index.css` (its layout is dashboard-specific, not shared with the test pages) and its two `<div class="volume-section">` blocks carry `id="vol2"`/`id="vol3"` so the breadcrumb on test pages (see below) can deep-link back to the right section.
- No page in the repo has an inline `<style>` block anymore — every page, including `index.html`, links external CSS from `assets/css/`.
- `assets/css/` holds the CSS shared by every test page, linked with `<link rel="stylesheet" href="../../assets/css/....css">` (two levels up from `Hacker{Vol2,Vol3}_Practice/TEST{NN}/`):
  - `common.css` — the full shared layout/theme (header, breadcrumb, bottom bar, score panel, question cards, options, buttons, responsive rules, etc.), identical across all 20 Listening and all 20 Reading pages, linked from every test page.
  - `listening.css` — the small delta only Listening pages need on top of `common.css`: sizing for the `.audio-player` (just the native `<audio>` control, no label text or toggle button — that was removed as unnecessary). Reading pages don't link this file since they have no audio player.
  - `index.css` — layout/theme for `index.html` only (dashboard grid, test cards); not linked from any test page.
  - `assets/images/` is currently unused — there are no images shared across tests; every image referenced from a page's `questionsData` (`image/NN.png`, `image/131-134.png`, etc.) is question-specific and lives in that test's own `TEST{NN}/image/` folder, not here.
- If you ever need to change shared styling, edit `assets/css/common.css` (or `listening.css` for the audio bar) once — it applies to all 20 tests automatically, unlike the old inline-`<style>`-per-page setup.
- **Color scheme (shared across the whole site, including `index.html`):** no `linear-gradient` anywhere — everywhere the old design used `linear-gradient(135deg, #667eea, #764ba2)` (page background, `.header`, `.passage-divider` in `common.css`; page background and `.header` in `index.css`) now uses the flat color `#8c9eef` (a ~75%-tint of the brand blue `#667eea` toward white). Since `.header` text sits directly on that lighter background, `.header`'s text color was changed from white to a dark navy (`#1e2749`) to keep it readable (white-on-`#8c9eef` failed contrast, ~2.5:1; navy-on-`#8c9eef` is ~5.7:1) — don't revert `.header`'s text color to white without also darkening its background back down, or it'll be close to unreadable. Smaller accent uses of `#667eea` (buttons, borders, badges like `.question-number`, links) were intentionally left as the original, more saturated `#667eea` in both `common.css` and `index.css` — only the large background areas were lightened, to keep those accents legible/vivid. Keep `index.css` and `common.css`/`listening.css` using the same two blues (`#8c9eef` backgrounds, `#667eea` accents, `#1e2749` on-light-blue text) so the dashboard and the test pages read as one visual system.
- **Breadcrumb / navigation:** every `ListeningTestNN.html`/`ReadingTestNN.html` has a `<nav class="breadcrumb">` right after `.header`, generated the same way on all 40 pages:
  - Left side (`.breadcrumb-trail`): `🏠 Home` (→ `../../index.html`) › `Hacker Volume {2,3}` (→ `../../index.html#vol{2,3}`) › current `Test {NN} · {Listening,Reading}` (plain text, not a link).
  - Right side (`.breadcrumb-nav`): a link to the sibling page for the same test (Listening ⇄ Reading), plus `‹ Test {NN-1}` / `Test {NN+1} ›` links to the previous/next test **within the same volume** (omitted at the volume's first/last test — no wraparound, and prev/next never cross Vol2 ↔ Vol3).
  - `.breadcrumb` is `position: fixed; top: 0` (max-width 1200px, centered, matching `.container`'s width) so it stays visible while scrolling; `.header` scrolls normally and disappears underneath it. `body`'s `padding-top` in `common.css` reserves space for it so the header isn't hidden on initial load.
  - This is generated, repetitive markup — if you add a new test or change the nav scheme, keep the same per-file link math (relative `../TEST{NN}/...` paths, `#vol2`/`#vol3` anchors) rather than hand-writing it inconsistently across files.
- **Part nav (in-page jump links):** right after `.breadcrumb` sits an empty `<nav class="part-nav" id="partNav"></nav>` in the static HTML — it's populated at runtime by `renderPartNav()` (added alongside `generateQuestions()` in all four `assets/js/` files, called from the same init function right before `generateQuestions()`), which builds one pill link per entry in `questionsData.parts`: `<a href="#part-N">Part N</a>`. `generateQuestions()` sets `id = 'part-' + part.partNumber` on each part's header div (the `.passage` div holding `<h2>Part N - Title</h2>`) so the links have something to jump to — Listening pages get 4 pills (Part 1-4), Reading pages get 3 (Part 5-7), purely driven by whatever parts exist in that test's `questionsData`, not hardcoded. It's a second `position: fixed` bar stacked right below `.breadcrumb` (`top: 70px`, same 1200px/centered sizing); `body`'s `padding-top` was increased in `common.css` to reserve space for both fixed top bars together. `.passage[id^="part-"]` gets `scroll-margin-top` in `common.css` so clicking a pill doesn't leave the target's heading hidden under the two fixed top bars. `.part-nav:empty { display: none; }` hides the bar entirely if `questionsData` somehow has no parts, rather than showing a blank white strip.
- **Bottom bar (score panel + audio player):** right after `.breadcrumb`, every test page has a `<div class="bottom-bar">` that is `position: fixed; bottom: 0` (same 1200px/centered sizing as the breadcrumb) — `body`'s `padding-bottom` in `common.css` reserves space for it. It replaces what used to be a separately-`sticky` score panel and a separately-fixed audio bar; now `.bottom-bar` alone owns the fixed positioning/background/border/shadow, and its children are plain flex items:
  - `.score-panel` (always present, `justify-content: space-between` on the parent keeps it flush left) — a single `.score-item` showing **Correct / Incorrect** as one compact `X`/`Y` value (green `<span class="correct">`, gray `<span class="score-sep">/</span>`, red `<span class="incorrect">` — same `#correctScore`/`#incorrectScore` element IDs the JS already targets, just spans instead of separate divs now), then a `.score-item` for **Progress** (`#totalScore`, e.g. `0/100`), then the **Reset Quiz** button. That left-to-right order (combined correct/incorrect → progress → reset) is deliberate — don't reorder without checking this note.
  - `.audio-player` (Listening pages only, sits to the right of `.score-panel` in the same bar) — just the native `<audio>` control, sized with `flex: 1 1 0; min-width: 0;` (`listening.css`) so it stretches to fill whatever width `.score-panel` doesn't use — a longer scrubber is easier to seek within. `.score-panel` has `flex-shrink: 0` so it always keeps its natural compact width instead of being squeezed by the growing audio bar. Reading pages' `.bottom-bar` contains only `.score-panel` and is narrower as a result.
  - If you touch this markup, keep it in sync across all 40 pages the same way as the breadcrumb — same structure, only the per-test audio filename (Listening) and IDs' values differ.
- `assets/js/` holds the rendering/grading logic shared by test pages (loading `questionsData`, generating question HTML, `selectAnswer`/scoring, `resetQuiz`):
  - `listening.js` — used by all 20 `ListeningTestNN.html` pages (byte-identical logic across all of them).
  - `reading.js` — used by 18 of the 20 `ReadingTestNN.html` pages (byte-identical logic across those 18).
  - `reading-vol3-test01.js` and `reading-vol3-test02.js` — dedicated files used only by `HackerVol3_Practice/TEST01/ReadingTest01.html` and `TEST02/ReadingTest02.html` respectively. Their original inline logic was a genuinely different (older-style) implementation — different function names (`loadQuestionsData`/`initializeQuiz`), a `confirm()`-gated reset, different answer-locking behavior — not a copy-paste duplicate of `reading.js`, so it was kept behaviorally unchanged in its own file rather than merged in. Don't casually swap these two tests onto `reading.js` — that would change their actual quiz behavior (e.g. the reset confirmation dialog, whether an answer locks after one try), not just refactor code.
  - All four files wrap each group of questions into a 2-column `<div class="question-grid">` instead of stacking them full-width, **unless any question in that specific group carries an `image`** — checked separately for each group with `.some(q => q.image)`. This applies at two levels in `generateQuestions()`: (1) a part's direct `part.questions` (Part 1/2 Listening, Part 5 Reading) — Part 2 and Part 5 don't have per-question images so they grid; (2) **each individual passage's** `passage.questions` (Listening Part 3/4, Reading Part 6/7) — even though the *passage* itself usually has an image/audio-graphic, that image is rendered once in the passage header, not per question, so the passage's own question group (e.g. "Questions 196-200") still grids into 2 columns below it. Each passage gets its own separate `question-grid` (not one grid spanning multiple passages), so odd counts (3 or 5 questions) just leave the last cell empty rather than misaligning across passages. The grid styling itself (`.question-grid`, incl. the `max-width: 700px` single-column fallback) lives in `common.css`. If you touch `generateQuestions()` in any of these four files, keep both has-image checks (part-level and per-passage) and the same wrapper-`<div>`-vs-`container` branching in the other three, or the pages will drift out of sync on this too.
  - Part 1 Listening (`listening.js` only — this is the one case where per-question `q.image` is actually set) instead gets a **left-image/right-content** layout: `questionDiv` gets a `with-image` class; its direct children are the `Question N` badge (`.question-number`, a plain sibling — deliberately *outside* the flex row, so it anchors to the top-left corner of the whole `.question-block` rather than the top of the content column) followed by a `.question-row` wrapping `.question-media` (the `<img>`) and `.question-content` (prompt, options, feedback), laid out `display: flex` in `common.css`. This is a *different* mechanism from `.question-grid` — it's a 2-column split *within one question card*, not multiple cards side by side — and `.question-row` falls back to a single stacked column below `600px` viewport width. If a future part ever needs both (per-question images *and* multiple cards per row), these two mechanisms compose fine since `.question-grid` only wraps whole `.question-block` elements and doesn't care about their internal layout.

**When adding or editing a test:** the Listening/Reading HTML files for a given volume are structurally near-identical (same CSS via `assets/css/`, and — for 38 of the 40 pages — the same JS logic via `assets/js/`) — when changing shared *behavior* (scoring, audio player, answer review), edit the relevant shared file in `assets/js/` and it applies everywhere that links it; only touch a page's inline `<script>` if you're changing that test's `questionsData`. Remember `HackerVol3_Practice/TEST01` and `TEST02` Reading pages use their own separate JS files (see above), so a `reading.js` fix won't reach them — check whether it needs to be ported there too. To start a new test page, copy an existing well-formed `ListeningTestNN.html`/`ReadingTestNN.html` (it'll already link the shared CSS/JS) and replace its `questionsData`, audio, and images — there are no separate template files in this repo.
